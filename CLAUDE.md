# Hyperplane Explorer

An interactive 4D explorer, plus three more pages: the 4D Rubik's cube (`rubik.html`), 4D chess (`chess.html`) and a 4D spinning cat (`cat.html`); see the end of this file. The viewer is a 3D being in a hyperplane of R⁴. The explorer's scene contains convex 4-polytopes, a glome, a w-thickened Earth, a Klein bottle, a 3D Klein bottle and a 4D Möbius strip; the cube page has a 3×3×3×3 Rubik's cube. Each can be shown three ways: **Slice** (intersection with your hyperplane), **Stack** (three parallel slices side by side), and **Shadow** (4D→3D perspective projection).

Vanilla JS + three.js **r187**, bundled with Vite. WebGL is the default; `?renderer=webgpu` uses `WebGPURenderer` with the TSL shaders, and `?renderer=webgpu-gl` forces its WebGL2 backend. There's no framework and no TypeScript yet.

## Commands

- `npm run dev` starts the dev server with HMR.
- `npm run build` writes a static build to `dist/`. `base: './'`, so it works from any path. `vite.config.js` lists all four pages as inputs and puts three.js in one shared chunk.
- `npm run preview` serves `dist/` on :4173.
- `npm test` runs the unit tests, then the Playwright smoke tests. `tests/smoke.spec.js` builds, serves, flips every view of the explorer, walks and tries volume view, and fails on any console or page error; `tests/rubik.spec.js` flips every view of the cube page, does a Diagonal view and a twist, and faces a Y layer in volume view; `tests/chess.spec.js` plays a move on the chess page, waits for the computer's reply and flips its views; `tests/webgpu.spec.js` runs every page and view on `WebGPURenderer`'s WebGL2 backend (nothing in the suite runs on real WebGPU yet: on headless software GPUs here, drawing to the canvas loses the device, but compute passes and drawing to a `RenderTarget` both work with `--enable-unsafe-webgpu --use-webgpu-adapter=swiftshader --enable-features=Vulkan`, and Playwright's Chromium 141 also rejects the `swizzle: 'rgba'` that three r187 passes to `createView`, so that has to be stripped first); `tests/walk.spec.js` checks that walking in the explorer draws what a fresh build draws; `tests/cat.spec.js` walks, steps ana and tilts on the cat page with YouTube blocked, flips its views, and tries the axis cross, the film strip and Best view (with trails). Screenshots go to `test-results/`. Run `npx playwright install chromium` once first. Where Playwright's bundled Chromium isn't available, set `PW_CHROMIUM_PATH` to another Chromium binary.
- `npm run test:unit` runs only the unit tests in `tests/unit/` with Node's built-in runner (Node 21+ for the glob). They cover `math4d.js`, `shapes/shapes.js`, `viewer.js`, the Rubik's cube model, the chess rules and AI, and the cat page's slice math (including cuts of a 4D ball) and model.
- `npm run landmask` regenerates `src/assets/land-mask.png` from Natural Earth 1:110m (world-atlas). Output is deterministic.
- Pushes to `main` run `.github/workflows/pages.yml`: unit tests, build, deploy to GitHub Pages. The smoke test doesn't run in CI.

## Layout

- `index.html` holds the markup: the viewport (`#view`) and the side panel (`<aside class="panel">`).
- `src/styles.css`: every color is a token on `:root`. The look is a single dark theme on purpose.
- `src/math4d.js` has the 4-vector and 4×4 helpers. Vectors are `[x,y,z,w]` arrays. Matrices are flat row-major arrays of 16. `rot(i,j,t)` is a Givens rotation in the i–j plane. `slerp(A,B,t)` interpolates rotations at constant speed via the Cayley transform (exact for single-plane turns, null at 180°); `jump.frame` uses it. `ease(t)` is the ease-in-out every tween on the three pages uses.
- `src/shapes/shapes.js` has the polytope generators: `{ verts, edges }`, centered, unit-ish. `klein()` is the exception: a closed triangle mesh `{ verts, tris, grid }` of a Klein bottle embedded in R⁴ (a ring in x–z whose tube circle turns through y–w). `spunKlein()` is the 3D Klein bottle S²×̃S¹, immersed (it must self-intersect in R⁴): fibers `{ c, M }` over u ∈ [0, π], each the ellipsoid `c + M·p` for p on the unit sphere, i.e. the glass Klein bottle with each circle bulged into a sphere through w. `mobius4()` is the 4D Möbius strip (a solid Klein bottle, Möbius strip × interval), embedded: disks `{ c, M }` over u ∈ [0, 2π], each `c + M·(a, b)` with a² + b² ≤ 1, flipping over through w as u goes around.
- **Shaders** live beside whoever uses them, each as GLSL for `WebGLRenderer` and a `.tsl.js` for `WebGPURenderer`; the two must be changed together. `src/shaders/` has the floor (shared, through the walker). `src/explorer/shaders/` has the Earth ray-caster (`globe.*`) and the cap surface for Shadow (`earth-cap.*`), both using `earth-surface.*`. `src/cat/shaders/` has the fur and its projection for Shadow (`fur-shadow.vert.glsl`, in `fur.tsl.js` for TSL). GLSL is imported with `?raw`; `earth.js` prepends `earth-surface.glsl`, and `fur.js` puts the model's landmarks ahead of `fur.glsl`. The TSL modules are loaded by top-level `await` only on `WebGPURenderer`, so the default pages don't download them. TSL rules learned the hard way: WGSL wants `fwidth` and texture reads outside any branch, a reversed `smoothstep` is written `1 − smoothstep`, uniforms don't belong inside `setLayout` functions (they came out under another material's names; the fur's colors are constants for this reason), depth goes through `viewZToPerspectiveDepth` so it doesn't depend on the backend's clip space, a nested `Loop`'s variable hides the outer one's (copy the outer one with `.toVar()` first), a `setLayout` parameter can't be a WGSL reserved word such as `as`, and WebGPU allows 8 vertex buffers per pipeline, which the WebGL2 backend doesn't enforce (`tests/webgpu.spec.js` counts them; interleave attributes to stay under).
- `src/scenery.js` and `src/hud.js` hold what the explorer and the cat page share. `scenery.js` has `tok` (read a CSS token), the 4D floor (`createFloor`), your marker, Shadow's depth shading (`depthShade`, `depthTint`) and the tube/knob instance matrices. `hud.js` has the position and frame readout, the ruler rows, where Stack cuts (`stackOffs`) and how its panels are labeled, `toScreen` (also used by chess) and the compass, a 2D canvas overlay of the world axes.
- **Shared modules vs pages.** Each page has its own folder (`src/explorer/`, `src/rubik/`, `src/chess/`, `src/cat/`) for code only it uses. Everything else is shared, and **a shared module never imports a page's state**: what it needs from a page comes in as arguments or a `ctx` object, so new pages and modules can use it without inheriting another page's choices.
- `src/utils.js` is the plumbing every page shares: `$`, `reduceMotion`, `createRenderer`, `press`/`onButton` for segmented buttons, `VIEW_KEYS` and `cameraTween` (eased orbit-camera moves and dollies, or `set` to land at once; orbiting by hand stops them). `environment.js` has `roomEnvironment` (the chrome's reflections), kept apart so the explorer doesn't load it.
- `src/shapes/` is the explorer's shapes. `shapes.js` is the geometry above. `draw.js` holds what they share, each taking your display frame V: `local`, `sectionPoints`/`sectionGeometry`/`addSection`, `projector`/`shadeAt`/`ridge` for Shadow, `addTubes`/`drawTubes`, `placeFibers`/`fiberExtent`. One module per kind (`polytope.js`, `earth.js`, `glome.js`, `klein.js`, `klein3d.js`, `mobius.js`) makes an entry's render objects and gives it `o.build(V, ctx)`, with ctx = `{ mode, labels, spinM }`; Earth also has `o.tick(camera, dt, reduceMotion)`. `world.js` has the shape definitions and `createWorld(scene, BG)`, which returns fresh entries and picks each one's kind. The Rubik's cube is the exception: its `o.build` is set by `createPuzzle`, which the page calls after `createWorld`.
- **The stage and the walker** are what the pages share. `src/stage.js` is the base for all four: `createStage` makes the renderer, scene, camera and orbit controls (with their eased moves), runs the frame loop (`stage.start({ before, after })`), and owns the view: Slice / Stack / Shadow, with its buttons, keys 1·2·3 and description. What a view *means* is the page's: it hears of a change in `onMode(m, prev)` and moves its own camera (the walker dollies out for Stack; chess frames each view). `src/walk.js` is the walker, a stage plus a viewer, for pages where you walk the world (the explorer, the cube page): `createWalker` adds the floor and you, your state (`you`, `S`, `VOL`, the display frame V, the redraw flag), the View / Move / Rotate panel and the position/compass overlay (markup in `src/nav.js`, put at `#nav`, `#nav-frame` and `#view` in the page), jumps (`startJump`, `frameOn`), volume view, and the loop that redraws the world once when something changed. A page gives `walker.run(world, hooks)` its world, a list of entries with `build(V, ctx)`, and hooks `mode`, `volume`, `spinM`, `tick`, `update`; its own panel sections go around `#nav`. Chess uses the stage alone, since its board has no free viewer. The walker's options set the camera, fog, floor and lights, and `hint` adds to the line at the bottom of the view; it returns the pieces a page needs (`scene`, `renderer`, `camera`, `view`, `S`, `VOL`, `startJump`, …), and the hooks also include `resize()` and `after(dt)` (once the camera has settled, just before drawing).
- `src/rubik/` is the 4D Rubik's cube and its page (`rubik.html`, `main.js`: the puzzle alone in a walker). `cube.js` is the puzzle as pure data (pieces, twists, scramble, animations, Mirror and Double rotation, solved check), tested in Node like the chess rules. `puzzle.js` draws it in each view and wires its panel, Face this layer and Diagonal view included. `createPuzzle(o, ctx)` takes the page's state and actions through `ctx` (`frame`, `mode`, `volOn`, `redraw`, `S`, `startJump`, `setVolume`, `frameOn`) and returns `{ step, explain, updatePanel }`; it sets the cube's `o.build(V, ctx)` itself. The walker is that `ctx`.
- `src/explorer/main.js` is the explorer page: the shapes (`shapes/world.js`) in a walker, with the shapes panel (the ruler, eye toggles), Earth's and the Möbius strip's state, and the Spin checkbox.

## Core model (read before editing)

**Viewer frame.** State `S = { P, R, U, F, A }`. P is a point and R/U/F/A is an orthonormal 4-frame: right, up, forward, ana.
- **U is locked to world y** (`[0,1,0,0]`). All slice rotations happen in the x–z–w subspace, via `rotatePlane` and `orthonormalize`, so the floor stays a floor. Don't break this casually: "Face this layer" can't face Y layers because of it, except in volume view.
- Your hyperplane is `{X : (X−P)·A = 0}`.

**Display frame.** Rendering reads `V`, not `S`. `V` shares P, R and F with S. Normally `V` is `S`; **volume view** (`VOL`, key V) tweens it 90° in the U–A plane to `(R, A, F, −U)`, so the slice lies level, your ana shows as up and R/F step through heights. Controls and frame ops (`act`, `rotatePlane`, `jump`, Face this layer, Diagonal view) act on `S`, so U stays locked. Code that draws or measures must read `V`; code that moves you must write `S`. In volume view the floor is parallel to the slice, so it drops away and hides, and copy that says ana/kata relative to the slice reads as down/up.

**4D → scene coordinates.** `local(V, X) = ((X−P)·R, (X−P)·U, −(X−P)·F)`, using the display frame `V` (P, R, U, F are its fields). The −F is because the three.js camera looks down −z. All scene geometry lives in these local coordinates; the scene origin is you.

**Rebuild loop.** Anything that changes 4D state calls `redraw()`. The frame loop calls `rebuild()` at most once, which calls every entry's `o.build(V, ctx)` to regenerate its geometry for the current view (`stage.mode()`). Geometry is rebuilt from scratch each time (cheap at this scale), and `clearGroup` disposes it. The exception is walking: an entry with `o.shifts` (everything but Earth in the explorer) draws entirely in `o.group`, so when only P changed the walker slides that group and moves `o.range` and `o.focus` instead of building. Shadow and Stack allow any move, Slice only moves within your hyperplane. Controls and jumps call `moved()`; anything else that changes the world calls `redraw()`, which always builds.

**Sectioning (Slice and Stack).** `sectionPoints(V, W, edges, off)` computes signed distances `dA = (v−P)·A − off` and lerps every sign-changing edge. `sectionGeometry` then classifies the point set (point / segment / planar polygon / solid) and hulls it with `ConvexGeometry`. This is exact for convex polytopes. `off` lets Stack cut parallel hyperplanes `P + off·A` without moving the viewer. `local(V, X)` is unaffected by `off` because A ⟂ R,U,F. The Klein bottle is a surface, so `cuts` (in `klein.js`) runs marching triangles over its mesh instead and the cut curves are drawn as instanced tubes. The 3D Klein bottle is cut analytically: each fiber ellipsoid meets the hyperplane in a circle, and `slice` (in `klein3d.js`) joins those circles into a tube, capped where a run of fibers ends. The 4D Möbius strip is cut disk by disk the same way: each disk meets the hyperplane in a chord, and `ribbonSlice` joins the chords into a ribbon, which is a Möbius strip exactly when it crosses every disk (after one lap the chord comes back reversed). Both use `placeFibers` and `fiberExtent`.

**Shadow.** `projector(V, C, E)` maps `X ↦ local(V, C) + (r·R, r·U, −r·F) · E/(E − r·A)` with `r = X − C`, i.e. an eye E units ana of the object's center. Polytopes draw edges as instanced tubes, shaded dim (kata) → bright (ana). The glome draws a Clifford torus plus two Hopf-linked great circles. Earth draws its two w-caps (projected sphere meshes) joined by rulings. The Klein bottle draws its projected skin (translucent), its tube circles, and the v = ±π/2 line as tubes; that line closes only after two laps. The 3D Klein bottle draws every 12th fiber sphere as three great circles plus the path of the poles p = (±1, 0, 0) as tubes. The 4D Möbius strip draws 16 of its disks as see-through cards and the path of their top points as tubes. The Rubik's cube draws each sticker as a small 3-cube in its cell, and the cell whose normal faces the eye (`n·A > 0.6`) is hidden. Shapes that differ only in w project onto the same spot; that's correct and documented in the UI.

**Earth** is `ball(R) × [−h, h]` in w, rendered per-pixel by ray-casting in `globe.frag.glsl`. Each fragment maps its ray to 4D (`Q + p.x·R + p.y·U − p.z·F`) and intersects the ball (a quadratic in xyz) with the slab (linear in w). The entry surface picks the shading: surface map or cut face with layer colors. It writes `gl_FragDepth`. Stack uses three proxies, each with its own `uQ` (slice offset) and `uShift` (sideways panel shift).

**Rubik's cube 3⁴** (`src/rubik/cube.js`).
- `cube.pieces`: 80 pieces, each `{ h, M }`. `h ∈ {−1,0,1}⁴ \ 0` is the home position. `M` is an integer 4×4 rotation, and the current position is `M·h`.
- A layer is `round((M·h)[axis]) === val`. A twist rotates that layer 90° in a plane (i, j) that excludes `axis`. When the animation finishes it is baked into `M` and rounded, so floating-point error never accumulates.
- Sticker color: map the face centroid back with `Mᵀu − h`; the dominant axis is the facet, and `h[i] === sign` means it's a sticker, otherwise plastic.
- `cube.O` is a display-only whole-puzzle rotation, used by Mirror and Double rotation. When it becomes an integer matrix and nothing is animating, `cube.step` folds it into every `M`. "Solved" is checked up to whole-puzzle rotation (`isSolved`). `cube.placed()` gives each piece's drawn rotation, with the twist under way.
- Colors (`CELL_COLORS`) are indexed `axis*2 + (sign>0)`: −X, +X, −Y, +Y, −Z, +Z, −W, +W.

**Animations.** `jump` tweens position, with an optional single-plane `turn` or a full `frame` (slerp; a frame exactly 180° away has no single path, so `startJump` lands it at once). `camTween` tweens the orbit camera. `cube.anim`, `cube.mirror` and `cube.spin` animate the cube, advanced by `puzzle.step(dt)`. Every animated action respects `prefers-reduced-motion`.

## Conventions

- Keep the math exact and honest. If a view is schematic (Stack's sideways shift), say so in the UI copy.
- New 4D objects: add an entry to the list in `shapes/world.js` and a module for its kind in `shapes/` that makes its render objects and sets `o.build(V, ctx)` handling all three modes (and pick the kind in `kindOf`). Each mode must set `o.range` (for the ana–kata ruler), and Stack must set `o.stackInfo = { spacing, bottom, labels }` so the panel labels can follow. Tapping a shape's name moves your slice to `o.focus` if set, else to the middle of `o.range`; the 4D Möbius strip sets it to the middle of the offsets where the slice is a Möbius strip.
- UI copy is short, plain and specific. Explanations live in `VIEW_DESC` (global views) and `EXPLAIN` (Rubik's cube views and tricks).
- Keyboard: W/A/S/D move, R/F height, E/Q ana/kata, J/L turn, I/K pitch into ana, U/O swing into ana, 1/2/3 switch views, V toggles volume view.

## 4D chess (`chess.html`, `src/chess/`)

A separate page. It runs on the stage (`stage.js`: renderer, camera, orbit controls, loop, and the Slice / Stack / Shadow buttons and keys) but not the walker, since the board has no free viewer: its "slice" is an ana axis and a layer.

- `rules.js` is pure and runs in Node. The board is an `Int8Array(256)` indexed `x + 4y + 16z + 64w`. A piece is ±type (`PAWN`…`KING`), positive for white. x is the file and y the level; z (rank) and w (layer) are both forward, from z = w = 0 (white) to 3 (black). Sliders move along the 80 directions in {−1,0,1}⁴ by order (how many axes change): rook 1, bishop 2, unicorn 3, queen any. The king takes one step and the knight jumps (2, 1). Pawns step +z or +w and capture forward plus ±x or ±y. They promote to a queen on z = w = 3 (black: 0). Precomputed rays per cell keep `attacked` and `pseudoMoves` fast. `gameState` gives play / check / checkmate / stalemate / draw (bare kings, or `quiet` ≥ 100 plies).
- `ai.js` is negamax with alpha-beta, depth 2, then a capture-only quiescence search. It uses pseudo-legal moves inside the tree, with a king capture counting as a win; only the root moves are fully legal. Piece values follow empty-board mobility: the rook (always 12 cells) is the weakest officer. `worker.js` runs it off the main thread. Replies carry a `token`, so a stale reply after undo or new game is dropped.
- `models.js` builds the piece geometry from lathes and extrusions. `buildStand` is the tri-d stand: a chrome column with arms to four glass plates, each `level` up and `stagger` back, merged into two meshes. `buildFrame` is the plain alternative, a wire outline with the levels stacked straight up. The View panel's Stand toggle switches `S.stand` between `STYLES.trek` and `STYLES.plain`, which differ only in `level` and `stagger`. The choice is kept in localStorage (`chess4d-stand`).
- `main.js` handles display and input. A change of view or a resize frames the camera through the stage's `onMode` and `onResize` (`FRAMING` has each view's camera). `FRAMES[ana]` picks which board axes show as right/up/forward; w takes the place of the axis your slice hides. `tower(k)` places 3D board k: side by side in Stack, only yours in Slice, nested about the board's `middle` by the 4D perspective factor `EYE/(EYE − (k − 1.5))` in Shadow. `place(cell)` gives a cell's target. Tiles (two `InstancedMesh`es, driven by stand-in Object3Ds), pieces, stands and markers all ease toward targets each frame, so moves and view changes animate for free. Picking raycasts pieces and tiles; in Shadow it prefers a legal target, then a piece, so you can reach the inner boards. `window.chess4d.cellOnScreen(name)` exists for the smoke test.
- The staggered levels and the gaps between boards are display only; the grid is regular. The copy says so where it matters.


## 4D spinning cat (`cat.html`, `src/cat/`, `src/viewer.js`)

A page: the OIIA OIIA meme cat spinning in 4D in front of a 4D TV that plays the song from YouTube. You walk it on the same walker (`walk.js`) as the explorer; `main.js` makes the cat and the TV two entries of its world, each with `build(V, { mode, labels })` and a `center` (the cat's moves along w in Pass through), and asks for a redraw every frame because both are always moving. It adds its own sections (Music, Spin, the ruler), Space to play, and the YouTube layer (`resize` and `after` hooks).

- `src/viewer.js` is the explorer's viewer model as a module: the frame `S` with U locked to world y, `act`/`rotatePlane`/`orthonormalize`, the volume-view display frame `frame()`, a position `jumpTo`, and `bindControls` for the same keys and on-screen `.key[data-act]` buttons. The walker (`walk.js`) is built on it, with its own `jump` on top for the turns of Face this layer and Diagonal view.
- Both are placed by a 4D center and an orientation matrix (`FACE` turns their front toward where you start). `slice4d.js` is pure and tested: `inView(V, C, M)` gives `G = Q·M` (rows R, U, −F, A of your display frame) and the center in your coordinates.
- **The TV is a thick object**: a 3D shape times [−h, h] along its own w. `thickSlice(G, h, off)` turns the cut at `off` into a 3×3 map L plus a shift and a slab of two clip planes. det L = 1/b, so the cut is mirrored when b < 0; edge-on (b ≈ 0, e.g. in volume view) b is clamped small, which draws the cross-section times the thickness. `main.js` draws it as three panels (Stack; Slice uses the middle one), each piece through `_m` with `clippingPlanes` and a BackSide copy in a flat cut color for the cut faces, swapping to a reversed-winding copy when mirrored.
- **The cat is round in w**, as round as it is in 3D. Each skin point s (normal n) has a `depth` r, how far in its part's middle is (model.js finds it by marching inward until the field stops falling at full rate). Turned θ into w it is at (s − r(1 − cos θ)·n, r sin θ), |θ| ≤ 90°: a ball becomes a 4D ball, a leg a round 4D tube. `roundCutter` cuts that surface: it samples θ at 17 shared steps, so each skin triangle and step is a prism; a prism crossed only on its three upright edges gives one triangle (a level cut through the middle is the skin itself), any other is split into three tetrahedra and marched. Upright crossings are exact roots of a(θ) = A + B cos θ + C sin θ; the rest are interpolated in (s, n, r, θ) and refined onto your hyperplane. It carries the fur attributes onto the new vertices and gives each its own w (`catW`). A cut costs 4–15 ms, so each of the three cut meshes is cut again only when its G or offset changes. On real WebGPU (not its WebGL2 backend) `shaders/cut.tsl.js` does the cut instead, with no GLSL copy: compute passes find the prisms your slice crosses and append one number per triangle (via `cutCases`, the cutter's cases as a table, tested against it), an indirect draw takes those, and the vertex shader finds each crossing from the source mesh, so nothing is uploaded per cut. Its triangles aren't wound, so it is double-sided with the normal unflipped. Its triangles are drawn as instances (3 vertices, one instance each), because Firefox silently skips an indirect draw that runs past its vertex buffers. Its vertices and offscreen pictures have been compared with the JS cutter's on the software adapter, and it has been seen drawing in Firefox on a real GPU. `roundRange` gives the cat's reach along your ana; `roundLayer` one layer at fixed w.
- **Spins** (`SPINS`, in `spins.js`, pure and tested in `tests/unit/cat-views.test.js`) are rotations in the cat's own coordinates, all back at the start after three turns (the loop's period): 3D (x–z), Through w (x–w), Both, Pass through (x–z plus a drift along w), Double (x–z and y–w), Opposite (its mirror image), 2 : 3 (x–z three turns to y–w's two) Somersault (y–w), Tumble (x–z, y–w and x–y at 3 : 2 : 1) and Wobble (x–z with a slow z–w and w–x roll). `window.cat4d.pose(spin, degrees)` stops the cat at a pose, for the smoke test. Each spin also has `turns` (1 or 3: how many turns bring it back) and `best`.
- **Views made for the spins** (`spins.js` has the math, `main.js` draws them). **Best view** (`BEST`) turns your slice to one that holds the spin's planes, where it is a plain 3D turn: level for x–z; pitched a quarter turn into ana (`FRAMES.front`, across z through the head) for x–w and y–w; volume view just under the top of the back for Both and Wobble, whose turns all stay in x, z, w. Double rotations and Tumble have no such slice, so it picks Shadow with trails. **Trails** (Shadow only) are the closed paths of five points (nose, ear tips, tail tip, socked paw) over one loop, projected from the cat's eye like its layers. **Cat views** replace the cat's cut in Slice: the **axis cross** (`CROSS`) is four cuts through the cat's rest center across world x, y, z and w, each in its own fixed frame; the **film strip** is eight poses over one loop (`filmAngles`), each cut by your slice, so they only re-cut when you move. Both hide the TV and draw from a pool of cut meshes (`cutAt`) shared with Stack; another view puts the cat back in your slice.
- Shadow: three of the cat's layers in w (its middle, and see-through ones at ±`LAYER_W`, only where parts reach) are projected in the vertex shader from an eye `EYE_CAT` ana of its center, so a frame only sets `catShadow.G` and `.at`. Each vertex keeps the sum of its triangles' 4D bivectors (`layerBivectors`), which gives its projected normal from six cross products of the map's Jacobian (`shadowVertex` is the same math in JS, for the tests); the TV's 4D box, its screen (a rectangle times the thickness), legs and rods are tubes from an eye `EYE_TV` ana of its center, shaded dim (kata) to bright (ana) as in the explorer.
- `model.js` builds Ethel, the meme's grey-brown tabby. The fur is one closed surface: a signed distance field (ellipsoids, round cones, cupped triangle ears, a tapered tail, joined with smooth minimums) meshed by surface nets at load (~0.65 s with the depths, ~18k vertices; slices and Shadow work per vertex each frame, so keep it small). Eyes, nose and whiskers are separate meshes. Attributes: `part`, `region` (head/leg/tail/inner-ear weights; body is the rest, so patterns blend across joins), `anchor`, `catPos`, `catW` (its own w; 0 on the skin, set by cuts and Shadow layers), `depth` and `shade`; `LAND` holds the landmarks the shader needs. `fur.js` is a `MeshStandardMaterial` patched with `onBeforeCompile` that paints the tabby pattern from `catPos` and `catW`, so it stays on the cat through slices and the shadow. The coat is a 4D pattern: noise is read at `catPos + catW·WDIR` and each stripe family has a w term in its phase, so stripes slide as you step ana or kata; at w = 0 it is the 3D coat, and the markings (muzzle, bib, toes, sock) don't move. Its tail curls to its right and its left front paw has a white sock, so a mirror image shows. `tests/unit/cat-model.test.js` checks the fur stays closed.
- **The beat** (`beat.js`, pure and tested in `tests/unit/cat-beat.test.js`): the song is 150 BPM and the default speed is one turn per beat. While the default video is really playing, `tick` steers the angle toward `songAngle(t)`, the short way round one turn, so only the turn is locked, not which of Both's three turns it is. `songClock` turns YouTube's few-times-a-second `getCurrentTime` into a steady clock. The Beat offset slider sets where a beat falls; other videos (`?v=`), reduced motion and a missing player run free. `window.cat4d.sync()` is for the smoke test, which uses a fake player.
- `tv.js` gives the TV's pieces (panel, glass, chrome), its 4D wire for Shadow, the antenna tesseract's center and the screen's place and pixel size.
- **The picture** is the YouTube IFrame player inside a `CSS3DObject` whose matrix comes from `screenSlice` (the thick screen's cut: affine, plus `poly`, the pixels inside the slab, applied as `clip-path`) or `screenShadow` (projective; CSS `matrix3d` draws the 4×4 as is). The CSS layer sits above the WebGL canvas, so no 3D object is drawn over the player; it hides when its back faces the camera, when nothing of it is in the slab, or when it is nearly edge-on. The music keeps playing while the TV is out of your slice. `?v=<id>` plays another video. YouTube refuses playback from some networks (this repo's cloud containers get its bot check), so the smoke test blocks YouTube.
